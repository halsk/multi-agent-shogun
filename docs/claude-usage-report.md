# claude-usage-report — Claude Code 利用状況の客観レポート

Claude Code が各自の端末に残すセッション記録から、トークンの使われ方を機械的に集計するスクリプトです。全員が同じコマンドを実行し、同じ形の出力を得ます。人による解釈や要約は入りません。

## このスクリプトは何を読み、何を読まないか(配布時にそのまま使える説明)

> このスクリプトは、Claude Code が端末に残す記録(`~/.claude/projects` 内の jsonl ファイル)から、トークン数の数値(input/output/キャッシュ読み書き)と、モデル名・effort・speed・作業ディレクトリ・ブランチ名・セッションIDなどのメタデータだけを取り出して集計します。プロンプト本文・会話の内容・ツールの入出力には一切アクセスしません。読み取るフィールドはスクリプト内の `extract()` 関数に列挙されているものがすべてで、それ以外のキーには触れず、出力(JSONと要約)にも会話内容は一切含まれません。スクリプトは260行ほどの単一ファイルですので、実行前に開いて中身をご確認ください。結果は人事評価・査定・社員間の比較には使いません。

## 使い方

```bash
python3 claude_usage_report.py                 # 全期間を集計
python3 claude_usage_report.py --days 30       # 直近30日のみ
python3 claude_usage_report.py --json out.json # JSONの出力先を指定(- で標準出力)
```

- 依存は Python 3.9+ の標準ライブラリのみ。インストール不要
- 出力は二本: 人が読む要約(標準出力)と機械可読 JSON(既定 `claude-usage-report.json`)
- 記録が無い端末では何も集計せず正常終了。壊れた行は読み飛ばして件数のみ報告

## 集計内容

モデル別トークン / キャッシュ読取率と書込TTL内訳(1時間/5分) / fast mode の割合 / service_tier / effort 分布 / リポジトリ別・ブランチ別 / 本体とサブエージェントの分離 / セッション数とセッションあたり出力 / web検索回数。

## 警告の閾値と根拠

| 警告 | 閾値 | 根拠 |
|---|---|---|
| キャッシュ読取率が低い | < 90% | 効率的な利用の実測基準線は 97.8%。公式ドキュメントも「キャッシュミスが直近利用の10%を超える」状態を要改善として扱う |
| fast mode の割合が高い | > 5% | fast は割高な出力モード。基準線は 0%(必要な場面に限る想定) |
| 5分TTL書込の比率が高い | > 20% | 基準線は約4%。比率が高い場合、usage credits 利用中にキャッシュ寿命が5分へ落ちている可能性が高い。`ENABLE_PROMPT_CACHING_1H=1` で1時間に保てる(最も費用対効果の高い設定) |

## 重複行の扱い(重要)

Claude Code の記録では、1つの API リクエストが複数行に分割され、**同じ usage が各行に複製される**ことがあります(実測では全行の約48%が複製)。本スクリプトは既定で `requestId` により1リクエスト1回だけ数えます。素朴に全行を合計すると実際の約2倍に過大計上されます。検証用に `--raw`(重複除外なし)も残してあります。

## 配布方法(提案・未確定)

社員が「開いて読んでから実行できる」ことが要件のため、単一ファイルのまま配るのが良い。候補:

- A. 社内リポジトリ(このリポ等)に置き、`curl -O <raw URL> && less claude_usage_report.py && python3 claude_usage_report.py` を案内
- B. GitHub gist(組織 secret gist)
- C. Slack にファイル添付(バージョン管理が効かないため非推奨)

いずれもワンライナー実行(`curl | python3`)は案内しない(読んでから実行する、の趣旨に反する)。
